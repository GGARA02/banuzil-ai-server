## 4. 모델 아키텍처

```
입력 텍스트: "[성별] {gender} [상황] {situation} [발화] {text}"
    ↓
Tokenizer (Max Length: 128)
    ↓
KcELECTRA Encoder (12 layers, hidden: 768)
    ↓
CLS Token → Dropout(0.1)
    ↓
    ├─→ Category Head (대분류)
    │       Linear(768 → 384) → GELU → Dropout(0.1) → Linear(384 → 6)
    │
    └─→ Detail Head (소분류)
            Linear(768 → 384) → GELU → Dropout(0.1) → Linear(384 → 63)
```

두 헤드를 **동시에 학습**하는 멀티태스크 구조다.  
대분류와 소분류가 같은 인코더를 공유하므로 표현 품질이 상호 강화된다.

## 5. 공통 하이퍼파라미터

| 항목 | 값 | 설명 |
|------|-----|------|
| **Max Sequence Length** | 128 | 토크나이저가 자르는 최대 토큰 수. 128을 넘는 발화는 뒤가 잘린다. 감성 발화는 대부분 짧아서 128로 충분. |
| **Epochs** | 5 | 전체 학습 데이터를 몇 번 반복 학습할지. 5회 반복 후 Val F1이 가장 높은 시점을 best_model로 저장. |
| **Train Batch Size** | 32 | 한 번의 가중치 업데이트에 사용할 샘플 수. 클수록 학습이 안정되지만 메모리 사용량 증가. |
| **Eval Batch Size** | 64 | 검증 시 배치 크기. 검증은 역전파가 없어서 메모리 여유가 있으므로 학습보다 크게 설정. |
| **Optimizer** | AdamW | Adam에 Weight Decay를 올바르게 적용한 버전. 트랜스포머 파인튜닝 표준 옵티마이저. |
| **Encoder Learning Rate** | 2e-5 | 인코더(KcELECTRA) 가중치 업데이트 속도. 사전학습된 가중치를 망가뜨리지 않도록 작게 설정. |
| **Head Learning Rate** | 1e-4 (Encoder × 5) | 분류 헤드 학습률. 헤드는 새로 만든 레이어라 처음부터 학습해야 해서 인코더보다 5배 크게 설정. |
| **Weight Decay** | 0.01 | L2 정규화 강도. 가중치가 지나치게 커지는 것을 억제해 과적합 방지. |
| **Warmup Ratio** | 0.1 (전체 스텝의 10%) | 학습 초반 10% 구간에서 학습률을 0에서 목표값까지 서서히 올림. 초반 불안정한 업데이트 방지. |
| **Dropout** | 0.1 | 학습 중 뉴런을 10% 확률로 무작위 비활성화. 특정 뉴런에 과의존하는 것을 막아 일반화 성능 향상. |
| **Attention Dropout** | 0.1 | 어텐션 가중치에 적용하는 드롭아웃. 특정 토큰에만 집중하는 과적합 방지. |
| **Scheduler** | Linear warmup + Linear decay | Warmup 구간 이후 학습률을 선형으로 감소. 후반부에 작은 학습률로 세밀하게 수렴. |
| **Seed** | 42 | 랜덤 시드 고정값. 데이터 셔플·드롭아웃 등 무작위 요소를 고정해 실험 재현성 보장. |
| **Loss (Category)** | CrossEntropyLoss, weight=0.6 | 대분류 손실 기여 비율 60%. 소분류보다 더 중요하게 취급. |
| **Loss (Detail)** | CrossEntropyLoss, weight=0.4 | 소분류 손실 기여 비율 40%. 63개 클래스라 난이도가 높아 낮은 비중으로 균형 조정. |

## 6. 모델 버전별 차이

세 가지 버전은 **데이터 가중치 전략**이 다르다. 아키텍처와 하이퍼파라미터는 동일.

| 버전 | 연애/결혼/출산 가중치 | 대인관계 가중치 | 기본 가중치 | 증강 배수 |
|------|---------------------|----------------|------------|---------|
| **weighted** | 5.0 | 2.0 | 0.3 | 2배 |
| **low_weight** | 3.0 | 1.5 | 0.5 | 1배 |
| **unweighted** | — | — | 1.0 | 0배 |

- **연애/결혼/출산** 상황에 높은 가중치를 준 이유: 커플 상담 서비스 특성상 이 상황의 발화가 실제 서비스에서 가장 많이 들어온다. 학습 데이터에서의 비율보다 실서비스 비율이 훨씬 높아서 보정한 것.
- **unweighted**: 가중치 없는 baseline. 전체 데이터를 균등하게 학습.
- **증강 배수**: 연애/결혼/출산 데이터를 N배로 복제해 학습 데이터에 추가하는 방식.

## 8. 현재 서비스 배치 구성

```python
# services/emotion_service.py
category_model = "models/unweighted"   # 대분류 Top-2 반환
detail_model   = "models/low_weight"   # 소분류 Top-3 반환
```

| 역할 | 모델 | 반환 |
|------|------|------|
| 대분류 | unweighted | 상위 2개 (label + score) |
| 소분류 | low_weight | 상위 3개 (label + score) |

**weighted 모델을 대분류에 쓰지 않는 이유:**  
Val Cat F1이 0.5587로 unweighted(0.5984)보다 낮다. 연애 상황에 가중치를 강하게 줬더니 오히려 전체 대분류 성능이 떨어졌다. 소분류(Det F1)도 마찬가지.  
대신 소분류는 low_weight가 가장 균형 잡힌 성능을 보여서 채택했다.
